Capsule 由志愿者以公开方式构建和支持。项目没有付费或私有的支持渠道：所有问题、报告和想法都通过项目的 GitHub 提交，任何人都可以回答，而这些回答也能帮助下一个人。安全漏洞是唯一的例外，需要私下报告。

Capsule 尚未发布任何版本；目前可用的功能和接下来的计划见[路线图](https://github.com/Capsulsaurus/Capsule/blob/master/ROADMAP.md)。

<a id="before-you-ask"></a>

## 提问之前

大多数问题都已经有答案。在这里花上一分钟，通常就能省去一次来回沟通。

1. **搜索文档**：使用每个页面顶部的搜索框，并阅读 [](/guides/troubleshooting/)，其中涵盖了常见故障以及如何收集日志。
2. **搜索[未关闭和已关闭的 issue](https://github.com/Capsulsaurus/Capsule/issues?q=is%3Aissue)** 以及[讨论区](https://github.com/Capsulsaurus/Capsule/discussions)。如果已经有人报告过，请添加 👍 表情回应，或发表包含新信息的评论，而不要重复提交。
3. **查阅命令接受的确切参数**：见 [](/reference/cli/)。

<a id="what-to-expect"></a>

## 你可以期待什么

- **志愿者的时间**。问题由社区和维护者在有空时回答，没有保证的响应时间。
- **完整的报告优先处理**。附有版本、复现步骤和日志的缺陷报告可以被确认并修复。缺少这些信息的报告需要先等待补充回复，之后才有人能着手处理。
- **一个主题一个帖子**。两个问题应分成两份报告，以便各自跟踪和关闭。
- **默认公开**。除漏洞报告外，所有内容都是公开的，因此在粘贴日志之前，请删去密码短语、恢复凭据、令牌、服务器地址和个人文件路径。
