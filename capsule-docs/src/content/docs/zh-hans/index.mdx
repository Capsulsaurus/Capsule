<a id="what-sets-capsule-apart"></a>

## Capsule 的与众不同之处

<FeatureGrid>
  <Feature icon="random" title="任意规模，井然有序" href="/features/smart-albums/" linkLabel="智能相册">
    搜索、智能相册和自动标记都设计为在你的设备上、基于完整的本地索引运行，因此即使照片库中有数百万张照片，也无需任何人手动整理，依然便于浏览。
  </Feature>
  <Feature icon="padlock" title="不持有密钥的服务器" href="/design/cryptography/" linkLabel="密码学设计">
    服务器只存储密文，从不持有密钥。它无法读取任何照片、说明文字或相册标题，却会为它接受的每一次上传签发一份托管回执。
  </Feature>
  <Feature icon="server" title="跨服务器共享" href="/design/federation/" linkLabel="联邦设计">
    信任建立在密码学之上，而不是服务器之上，因此不同 Capsule 服务器上的用户可以互相共享相册，中间没有任何中心化服务。
  </Feature>
  <Feature icon="laptop" title="完整照片库，离线可用" href="/features/offline-library/" linkLabel="离线照片库">
    每个原生应用都设计为保存你留存的每一张照片的完整索引，因此无需联网即可浏览、搜索和整理全部内容。
  </Feature>
  <Feature icon="approve-check-circle" title="可验证的历史" href="/design/cryptography/provenance/" linkLabel="来源设计">
    每个资源都带有一条经过签名、只可追加的来源链，因此是哪个人、哪台设备导入或编辑了它，都经过验证，而不是凭信任接受。
  </Feature>
  <Feature icon="database" title="从设计上可恢复" href="/design/backup-recovery/" linkLabel="备份与恢复">
    每个资源都配有一个经过签名的元数据附属文件（sidecar），因此即使没有数据库，照片库依然可读，并能从部分损坏中重建。
  </Feature>
</FeatureGrid>

<a id="everything-you-would-expect"></a>

## 你期待的功能，一应俱全

原始文件以完整质量保存，可逐字节还原。RAW 和视频都是一等支持的格式。原生应用采用各平台自己的控件构建。CLI 和 TUI 能完成应用能做的一切；参见 [](/reference/cli/)。

<a id="why-it-is-built-this-way"></a>

## 为什么这样构建

大多数照片服务都让你二选一：要么获得服务器通过读取你的照片库才能提供的功能，要么获得服务器无法读取时才有的隐私。Capsule 选择了隐私，并在你的设备上、基于只有它们才能解密的数据，重新构建了这些功能。

这一选择是有代价的，设计文档会如实说明，而不是将其隐藏：不持有密钥的服务器能告诉你什么、不能告诉你什么（[](/design/notifications/)），密钥丢失时会发生什么（[](/design/backup-recovery/#recovery-paths)），以及有缺陷或恶意的客户端会被阻止做什么（[](/design/threat-model/)）。
