このガイドでは、リファレンスクライアントである`capsule` CLIを扱います。（*予定*）と付いたコマンドは[ロードマップ](https://github.com/Capsulsaurus/Capsule/blob/master/ROADMAP.md)に載っているもので、まだ利用できません。フラグについては`capsule <command> --help`が正確な情報源で、CLIリファレンス（[](/reference/cli/)）にすべて掲載されています。

:::caution
Capsuleはアルファ版です。最初のドッグフーディング版がリリースされるまでは、取り込んだオリジナルについて、別途独立したバックアップを保持してください。
:::

<a id="set-up"></a>

## セットアップ

1. ライブラリを作成します：`capsule library init --name "Photos"`。ライブラリはローカルの暗号化されたディレクトリで、そのパスフレーズがこのマシン上の鍵を保護します。
2. サーバーにサインインします：`capsule auth register`または`capsule auth login`（シングルサインオンには`--oidc`または`--device`）。
3. 復旧を設定します：`capsule auth escrow`。表示されたリカバリーシークレットはオフラインで保管してください。これとパスフレーズの両方がなければ、マシンを失うことはライブラリを失うことを意味します。サーバーは何も復号できないためです。

<a id="import-and-back-up"></a>

## 取り込みとバックアップ

- `capsule import <path>`はファイルをライブラリにコピーし、各アセットの来歴とメタデータに署名して、サムネイルを生成します。`--provider takeout`は、Google Takeoutのエクスポートをサイドカーのメタデータごと取り込みます（[](/guides/google-photos-migration/)）。
- `capsule push`はライブラリをアップロードします。アップロードは中断したところから再開されるため、`push`を再実行しても常に安全です。`push`はアセットごとに、すべてのblobを永続的に保持していることをサーバーに確認させ、サーバーが署名した保管受領証をライブラリに保存します。失敗したアセットは報告され、処理はそのまま続行されます。いずれかのアセットが失敗した場合、コマンドは0以外の終了コードで終了し、`--json`は各アセットの結果を一覧表示します。
- `capsule import --push`は両方を1回で行います。
- **保管が検証されるまで、オリジナルを手元に残してください**。アセットが安全に保存されたといえるのは、サーバーが永続化を報告し、署名付きの保管受領証を発行したとき（`push`はこれを検証済みと報告します）だけです。それまではソースファイルを削除しないでください。`import --move --push`は、各アセットが検証された後にのみ、そのソースを削除します。`--push`を付けない場合、`--move`はすべてのソースを残し、その旨を表示します。後で同じファイルに対して`import --move --push`を実行すると、それらが解放されます。
- `capsule restore`（*予定*）はオリジナルをダウンロードし、取り込み時に署名された内容とバイト単位で照合します。

<a id="organize"></a>

## 整理

- **ラベル**は自由形式で、アセット、スタック（RAW+JPEGのペア、連写、ブラケット撮影）、アルバム、または画像内の領域に付けられます。自分で付けたラベルはAIが提案したラベルとは別に保持され、提案は採用することも却下することもできます。アセットのラベルは現在利用できます。スタック、アルバム、領域のラベルは（*予定*）です。
- `capsule show <asset>`は、アセットの署名付きメタデータに記録されている内容（キャプション、レーティング、ラベル、位置情報、撮影日時）を表示します。
- `capsule repair capture-time`は、撮影日時がオリジナルのEXIFと一致しないアセットを見つけ、`--apply`を付けると修正します。位置情報の編集は（*予定*）です。

すべての編集は、署名付きで追記のみの変更です。以前の値はアセットの来歴の履歴に残り、2台のデバイスからの同時編集は決定論的にマージされます。

<a id="delete-safely"></a>

## 安全な削除

位置情報などのメタデータは、周囲のアセットがまだ手がかりを与えてくれるうちに、削除する前に修正してください。それ自体に位置情報のない写真でも、同じ散歩で撮った前後の写真がライブラリにあるうちは場所を特定しやすいものです。それらがなくなれば、その手がかりも失われます。

- `capsule cull`はアセットに採用、未決定、不採用のフラグを付け、フラグで絞り込みます。
- `capsule cull --sweep`は不採用のアセットをゴミ箱に移動します。ゴミ箱に入れたアセットは、完全に削除されるまでの保持期間（`--retain-days`）中は復元できます。
- `capsule trash delete --asset <id>`は、ライブラリだけでなくサーバー上でもアセットをゴミ箱に移動します。すでにゴミ箱にあるアセット（たとえば`capsule cull --sweep`の後）は、ゴミ箱に入れられたときの保持期間をそのまま保ちます。`--retain-days`は新たな削除にのみ適用され、`--json`は送信した期間を`retention_until`として報告します。
- `capsule trash restore --asset <id>`はアセットを元に戻します。保持期間が終わった後の復元は拒否され（`--json`では`retention_elapsed`）、再試行もされません。そのアセットは完全に削除されるまでゴミ箱に残ります。

<a id="share"></a>

## 共有

- `capsule share create --album <id>`または`--asset <id>`は、閲覧専用のリンクを発行します。`--protect`はリンクにパスフレーズを追加し、`--expires-at`は有効期限を設定します。リンクの鍵はURLのフラグメントに含まれ、サーバーに届くことはありません。
- `capsule share revoke <id>`は、リンクを開けないようにします。

<a id="sync-another-machine"></a>

## 別のマシンとの同期

- `capsule sync`はライブラリの変更フィードをサーバーから取得し、`capsule list`はそれによって届いた内容を表示します。
- `capsule auth recover`は、リカバリーシークレットを使って新しいマシンにアカウントを復旧します。
