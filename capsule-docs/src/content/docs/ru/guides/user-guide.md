Это руководство описывает CLI `capsule` — эталонный клиент. Команды с пометкой *(в планах)*
есть в [дорожной карте](https://github.com/Capsulsaurus/Capsule/blob/master/ROADMAP.md), но
пока недоступны. Для флагов авторитетный источник — `capsule <command> --help`; все они
перечислены в справочнике CLI ([](/reference/cli/)).

:::caution
Capsule находится в стадии альфа-версии. До первого внутреннего (dogfood) выпуска храните
независимую резервную копию каждого импортируемого оригинала.
:::

<a id="set-up"></a>

## Настройка

1. Создайте библиотеку: `capsule library init --name "Photos"`. Библиотека — это локальный
   зашифрованный каталог; её парольная фраза защищает ключи на этом компьютере.
2. Войдите на свой сервер: `capsule auth register` или `capsule auth login` (`--oidc` или
   `--device` для единого входа).
3. Настройте восстановление: `capsule auth escrow`. Храните выведенный секрет восстановления
   офлайн. Без него и без парольной фразы потерянный компьютер означает потерянную библиотеку,
   потому что сервер ничего не может расшифровать.

<a id="import-and-back-up"></a>

## Импорт и резервное копирование

- `capsule import <path>` копирует файлы в библиотеку, подписывает происхождение и метаданные
  каждого объекта и создаёт миниатюры. `--provider takeout` импортирует архив Google Takeout
  вместе с его файлами-спутниками метаданных ([](/guides/google-photos-migration/)).
- `capsule push` загружает библиотеку на сервер. Загрузка продолжается с места остановки,
  поэтому повторный запуск `push` всегда безопасен. После каждого объекта `push` просит сервер
  подтвердить, что тот надёжно хранит каждый блоб, и сохраняет в библиотеке подписанные
  сервером квитанции о хранении. Об объекте, загрузка которого не удалась, сообщается, и работа
  продолжается. Если хотя бы один объект не загрузился, команда завершается с ненулевым кодом,
  а `--json` выводит результат по каждому объекту.
- `capsule import --push` делает и то и другое за один шаг.
- **Храните оригиналы, пока хранение не подтверждено.** Объект надёжно сохранён только тогда,
  когда сервер сообщил, что он записан надёжно, и выдал подписанную квитанцию о хранении, —
  `push` отмечает такой объект как проверенный. До этого не удаляйте исходные файлы.
  `import --move --push` удаляет каждый исходный файл только после проверки его объекта. Без
  `--push` флаг `--move` сохраняет все исходные файлы и сообщает об этом, а последующий запуск
  `import --move --push` для тех же файлов освобождает их.
- `capsule restore` *(в планах)* скачивает оригиналы и сверяет их байт в байт с тем, что было
  подписано при импорте.

<a id="organize"></a>

## Упорядочивание

- **Метки** задаются произвольно и прикрепляются к объекту, стопке (пара RAW+JPEG, серия,
  брекетинг), альбому или области изображения. Добавленные вами метки хранятся отдельно от
  предложенных ИИ, и предложение можно принять или отклонить. Метки объектов уже работают;
  метки стопок, альбомов и областей — *(в планах)*.
- `capsule show <asset>` выводит то, что записано в подписанных метаданных объекта: подпись,
  рейтинг, метки, местоположение, время съёмки.
- `capsule repair capture-time` находит объекты, время съёмки которых расходится с EXIF
  оригинала, и с флагом `--apply` исправляет его. Редактирование местоположения — *(в планах)*.

Каждая правка — это подписанное изменение, которое только добавляется в журнал: прежнее значение
остаётся в истории происхождения объекта, а одновременные правки с двух устройств объединяются
детерминированно.

<a id="delete-safely"></a>

## Безопасное удаление

Исправляйте метаданные, например геопозицию, до удаления, пока соседние объекты ещё дают
контекст. Фотографию без собственного местоположения легко привязать к месту, пока в библиотеке
есть её соседи с той же прогулки; когда их не станет, исчезнет и этот контекст.

- `capsule cull` помечает объекты как выбранные, нейтральные или отклонённые и фильтрует по
  отметке.
- `capsule cull --sweep` перемещает отклонённые объекты в корзину. Объекты в корзине можно
  восстановить в течение периода хранения (`--retain-days`), после чего они удаляются
  окончательно.
- `capsule trash delete --asset <id>` перемещает объект в корзину и на сервере, и в библиотеке.
  Объект, который уже в корзине, например после `capsule cull --sweep`, сохраняет период
  хранения, с которым он туда попал: `--retain-days` действует только для нового удаления, а
  `--json` сообщает отправленный период как `retention_until`.
- `capsule trash restore --asset <id>` возвращает объект. Восстановление после окончания
  периода хранения отклоняется (`retention_elapsed` в выводе `--json`) и не повторяется; объект
  остаётся в корзине, пока не будет удалён окончательно.

<a id="share"></a>

## Общий доступ

- `capsule share create --album <id>` или `--asset <id>` создаёт ссылку только для просмотра;
  `--protect` добавляет к ссылке парольную фразу, а `--expires-at` — срок действия. Ссылка
  несёт ключ во фрагменте URL, который никогда не попадает на сервер.
- `capsule share revoke <id>` отключает ссылку.

<a id="sync-another-machine"></a>

## Синхронизация другого компьютера

- `capsule sync` получает с сервера ленту изменений библиотеки; `capsule list` показывает, что
  было получено.
- `capsule auth recover` переносит учётную запись на новый компьютер с помощью секрета
  восстановления.
